# Barracuda X Chroma command-line guide

For an existing working installation, keep your current USB permission rule.
The headset backend is still v0.1.0-experimental; GUI releases have a separate version.

## First step

Connect the headset's **2.4 GHz USB dongle**, turn the headset on and select
2.4 GHz mode. Extract this archive and open a terminal in `barracuda-linux`.
Run the following as your normal desktop user:

```bash
python3 barracuda.py diagnose
```

This only reads Linux device metadata. It sends **no USB commands** and changes
no settings. Expected: one `1532:0574` device and both capabilities `true`.
If nothing is found, run `lsusb -d 1532:` and share the output before proceeding.
Different IDs or layouts need review; this build deliberately does not guess.

## Enable access

If `readable` or `writable` is false:

```bash
bash install-permissions.sh
```

Unplug and reconnect the dongle, then repeat `diagnose`. The script installs one
device-specific rule granting HID access to the active local desktop user. It
does not change the audio driver, add you to groups or make the device globally
writable. Run the controller itself without sudo.

Close other controllers targeting the headset before trying:

```bash
python3 barracuda.py status
```

This sends queries but no setting changes. Share any errors before trying audio
writes. If queries fail, capture passive reports instead:

```bash
python3 barracuda.py watch --seconds 30
```

While watching, toggle the headset's mic-mute button. The capture reads only
vendor status reports from this specific dongle; it does not record audio.

## Desktop controls

The new GUI uses PyQt6. On Arch/CachyOS, install `python-pyqt6` as shown above,
then run `python3 barracuda.py gui` from the extracted directory.

- **Overview:** last queried battery, EQ preset, monitoring and timeout.
- **Sound:** preset buttons, ten custom sliders, sidetone and power settings.
- **Lighting:** all-zone swatches, individual colors, brightness and effects.
- **Diagnostics:** permission check, response details and copy button.

A status refresh loads unedited controls from the headset. Controls you have
edited retain their pending values. The dashboard shows confirmed device values.
The minimum window size is 980×700; smaller layouts scroll vertically. The app
uses Qt's normal display scaling and keyboard focus.

## Implemented controls

| Control | This build |
| --- | --- |
| Battery / charging | Active queries; passive status capture |
| EQ | Preset selection and custom ten-band curve |
| Sidetone | Enable/disable and level |
| Idle power-off | Off, 15 or 30 minutes |
| RGB | Six colors, brightness, off, firmware control |
| RGB animation | Breathing, spectrum and wheel, generated by this process |
| Playback / microphone volume | Use the desktop audio settings |

Audio writes require a successful query first and matching post-write readback.
RGB reports have no color readback, so their messages say **sent**, not verified.
Test one control at a time. Reduce playback volume before changing EQ or
sidetone. The custom EQ range of −6…+6 is a conservative limit imposed by this
tool, not the headset's documented maximum.

## Command-line examples

Run from the extracted directory after the read-only checks above succeed.

```bash
python3 barracuda.py preset music
python3 barracuda.py eq 2 2 1 0 -1 1 2 3 2 2
python3 barracuda.py sidetone 20
python3 barracuda.py sidetone on
python3 barracuda.py sidetone off
python3 barracuda.py sleep 15
python3 barracuda.py rgb 00FF80 --brightness 40
python3 barracuda.py rgb FF0000 FFFF00 00FF00 00FFFF 0000FF FF00FF
python3 barracuda.py rgb 000000
python3 barracuda.py effect wheel --seconds 30
python3 barracuda.py rgb-release
```

EQ gains are ordered low to high. A curve operation selects Custom first; if the
second operation fails, the error says the preset may already have changed.
Setting a sidetone level does not enable sidetone. Static RGB is left in place
when the program exits; effects request firmware lighting when stopped.

If there are multiple matching devices, place `--device /dev/hidrawN` **before**
the command, using a path returned by `diagnose`. Never guess a hidraw number.

## Scope and validation limits

- No firmware updating, Razer account/cloud profiles, game-linked profiles,
  Chroma Studio integration, display/idle lighting policy or proprietary 7.1
  processing. Normal USB audio remains managed by Linux.
- Bluetooth-only operation and Bluetooth settings are outside this controller.
  Razer's official Audio mobile app lists this headset as supported and is an
  alternative for the settings it exposes.
- Hardware protocol observations come from headset owners, not a Razer API
  guarantee. GET/SET report framing still needs validation on your firmware.
  In particular, the SET length formula is inferred from published GET/reply
  lengths, and reply checksum coverage is accepted using either of the two
  documented coverage ranges. The selected range appears in `status` output.
- No automatic write retries. If a write was sent but readback fails, the
  outcome is reported as unknown. Re-query before making another change.
- USB dongle presence alone does not prove that the headset is connected.
  An observed link-loss event invalidates cached data. Queries can time out if
  the headset is off, using Bluetooth or another app owns its status stream.
- Offline unit tests validate packet layout, input guards and failure handling.
  Their replies are synthetic. Passing them does **not** establish hardware
  compatibility. The Qt GUI was rendered and visually inspected, and its
  controls were tested against a simulated controller. Hardware confirmations
  above were reported by the user on the earlier GUI with the same backend.

Run the backend checks with `python3 -m unittest -v test_barracuda.py`.
With PyQt6 installed, run all 36 checks with:

```bash
QT_QPA_PLATFORM=offscreen python3 -m unittest -v test_barracuda.py test_gui.py
```

## Remove

Close the controller and delete the extracted folder. To remove its permission
rule as well:

```bash
sudo rm -- /etc/udev/rules.d/70-barracuda-x-chroma.rules
sudo udevadm control --reload-rules
```

Reconnect the dongle. This does not roll back settings already stored by the
headset. Query and set those individually, or use the official Razer software.
